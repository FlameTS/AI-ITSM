## 1. What Was Implemented

The M2 notification/update feature was implemented and integrated into the existing ASP.NET Core application.

Workflow:

```text
Notification record
      ↓
NotificationService
      ↓
NotificationController
      ↓
Employee Notification UI
      ↓
View notification
      ↓
Mark as Read
      ↓
Persist IsRead = true
```

The employee can view their notifications, see unread notifications, open a related incident when available, and mark notifications as read.

## 2. Why It Was Implemented

Employee incident notifications/updates are part of the M2 Extensions + Integration responsibility.

The existing `Notifications` table was reused. M7 remains responsible for n8n automation and escalation; this implementation provides the employee-facing persisted notification functionality without rebuilding M7.

## 6. User Security / Ownership

Notification retrieval uses the current application user through:

```csharp
_currentUser.UserId
```

Mark-as-read verifies both the notification ID and current user ID before changing `IsRead`.

## 7. UI Behavior

The notification page displays unread state, message, creation time, a Mark as Read action, and a View Incident link when `IncidentId` is available.

After marking a notification as read:

- Unread badge disappears.
- Mark as Read button disappears.
- Notification remains visible.
- View Incident remains available.
- Refresh preserves the read state.

## 9. Issues Encountered

### Razor View Compilation Error

The initial Razor file produced C# syntax errors because the file was not being interpreted correctly as Razor. The `.cshtml` view was corrected.

### NullReferenceException

The first runtime attempt failed at:

```csharp
ViewData["Title"] = "Notifications";
```

The database query had already succeeded. The unnecessary `ViewData` assignment was removed, after which the page rendered correctly.

## 10. Design Decisions

- Reuse the existing Notifications table.
- Keep employee notification viewing/read-state functionality in M2.
- Do not reimplement n8n automation owned by M7.
- Use the current user rather than client-supplied user IDs.
- Use persisted notifications rather than introducing real-time/WebSocket infrastructure not required for this scope.
