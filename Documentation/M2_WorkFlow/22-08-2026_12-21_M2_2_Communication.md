## 1. What Was Implemented

The first M2 Extensions + Integration feature, **Incident Communication / Comments**, was implemented end-to-end.

Workflow:

```text
Employee
    ↓
My Incidents
    ↓
Incident Details
    ↓
Communication
    ↓
View existing comments
    ↓
Add comment
    ↓
IncidentCommunicationController
    ↓
IIncidentCommentService
    ↓
IncidentCommentService
    ↓
AIITSMDbContext
    ↓
IncidentComments
    ↓
SQL Server
```

The employee can open an incident, view existing comments, add a comment, receive success feedback, and see the persisted comment after refresh.

## 2. Why It Was Implemented

Communication between the employee and support/agent side is part of the documented M2 employee incident workflow.

The implementation reuses the existing `IncidentComments` database structure instead of inventing a separate communication mechanism.

## 10. Design Decisions

### Reuse Existing IncidentComments Table
No new communication table was invented because the database already provides `IncidentComments`.

### Use Existing Shared DbContext
A second M2 DbContext was not introduced. The existing shared `AIITSMDbContext` was extended.

### Extend Existing Incident Details UI
Communication was integrated into the existing Incident Details page.

### Use Current User Service
`UserId` comes from `ICurrentUserService`, not from user-controlled form input.

### Keep Scope Limited
No advanced chat functionality was added. The feature provides basic incident-linked communication appropriate to the documented project scope.
