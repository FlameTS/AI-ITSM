AI-Powered IT Service Management and Incident Resolution Platform (AI-ITSM)

## Purpose
This document records the division of M2 — Incident Management work between the two current M2 contributors.

```text
    ↓

```

## Parallel Development Rule

Both contributors may work simultaneously.

To reduce Git conflicts:

1. Avoid editing the same source file at the same time.
2. Keep work inside the M2 module structure where possible.
3. Coordinate before changing shared files such as `Program.cs`, shared DbContext/configuration, shared layout files, or common models.
4. Pull/rebase/merge carefully before integration.
5. Keep commits focused on one completed piece of work.

## Documentation Checkpoint Rule

After each major completed M2 piece, create a Markdown checkpoint.

Naming convention:

```text
DD-MM-YYYY_HH-MM_M2_2_<ShortDescription>.md
```

Examples:

```text
22-08-2026_15-00_M2_2_InitialDivision.md
22-08-2026_16-30_M2_2_Communication.md
22-08-2026_18-00_M2_2_Attachments.md
22-08-2026_20-00_M2_2_Feedback.md
22-08-2026_22-00_M2_2_M6_Integration.md
```

Each checkpoint should record:

- What was implemented
- Why it was implemented
- Requirements covered
- Files changed
- Database changes
- Integration/dependencies
- Testing performed
- Current status
- Remaining work
